# 11. Glossary

Every term this guide uses, in plain language.

### Aggregate function
The way a dashboard panel turns many records into one number — count, sum, average, minimum or maximum. See [Building dashboards](06-dashboards.md).

### API
A way for other software to read and write your data directly, without a person clicking anything.

### API key
A long password given to a program rather than a person, controlling what that program may do. See [Connecting other systems](10-connecting-systems.md).

### Collection
A container for one kind of thing — "Customers", "Products". Like a spreadsheet. See [Working with collections](02-collections.md).

### Condition
A rule making a field appear, become required, or grey out depending on other values. Also the automation step that chooses between two paths.

### Dashboard
A page of summary numbers, charts and lists. See [Building dashboards](06-dashboards.md).

### Draft
The version of an automation you're editing. It doesn't run until you publish it. See [Automations](09-automations.md).

### Field
One piece of information recorded about every item in a collection — "Email address", "Price". Like a spreadsheet column. See [Adding and editing fields](03-fields.md).

### Filter
A set of rules that narrows a list to matching records. See [Finding the records you need](05-finding-data.md).

### Flow
Studio's word for an automation. See [Automations](09-automations.md).

### Label
The friendly name shown to people, as opposed to the internal name used behind the scenes.

### Locale
A language. A panel with multilingual content turned on can hold a separate version of some fields per locale.

### Operation
A single step inside an automation — send an email, update a record, call another system.

### Panel
One box on a dashboard: a number, a chart or a short list. (Confusingly, "panel" also sometimes means the whole admin site — context usually makes it clear.)

### Permission
A single thing someone is allowed to do, such as *delete customer records*. Bundled into roles. See [Controlling who can do what](08-permissions.md).

### Published
The live version of an automation — the one that actually runs. Distinct from the draft you're editing.

### Record
One entry in a collection — one customer, one product. Like a spreadsheet row. See [Adding and editing records](04-records.md).

### Required
A field that must be filled in before a record can be saved. Shown with a red asterisk.

### Role
A named bundle of permissions given to people — "Editor", "Viewer". See [Controlling who can do what](08-permissions.md).

### Saved filter
A filter kept for reuse, optionally shared with colleagues. See [Finding the records you need](05-finding-data.md).

### Singleton
A collection holding exactly one record, used for settings pages like "Company Details".

### Slug
The web-address-friendly version of a name: "My Blog Post" becomes `my-blog-post`.

### Soft delete
Deleted records are hidden rather than destroyed, so they can be recovered. See [History and undoing mistakes](07-history-and-recovery.md).

### Tenant
In a panel serving several organisations, one of those organisations. Each tenant's data is kept entirely separate.

### Trigger
What starts an automation — a schedule, a record changing, a button press, or an outside system calling in.

### Unique
A field where no two records may hold the same value, such as an email address.

### Version / version history
A saved snapshot of a record as it was at one moment, and the list of all such snapshots. See [History and undoing mistakes](07-history-and-recovery.md).

### Webhook
A web address another system can call to start one of your automations.
